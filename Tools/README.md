# Tools

End-to-end checks on the real screen. Not shipped in the app, and not run by `scripts/check`, because they switch apps and dim the display.

- **`./e2e.sh`** runs the real DimmingEngine, GammaController, ActivationMonitor and FrontWindowTracker, switches between Terminal and Finder, and reads every result back with `peek`. It then checks the safety net through the real `SafetyNet` and watchdog (built straight from `App/GammaWatchdog`): termination signals, `kill -9`, main-thread stalls under 1 s, the watchdog's idle CPU, `kill -STOP` restored within 2 s and faded back on `kill -CONT`, and a killed watchdog being replaced. Last it checks paused displays with `other-app` standing in for f.lux: another app's table pauses the display within about 3 s without a fight, Resume dims on top of it, a second takeover pauses again, and another gamma writer quitting is re-applied within about 1 s without pausing. It prints `ok` or `FAIL` per step, plus the harness logs if anything failed, and exits non-zero on any failure. It takes about a minute and a half, and refuses to start while Cathemeral is running, because a second gamma writer spoils the readings.
- **`switch-timing`** (`swift run switch-timing <bundle-id> <bundle-id> [rounds]`) switches between two apps and fails if either app is ever shown brighter than its own level (brightening must wait until the new app's window is in front, and dimming must be done by then), if a switch jumps instead of fading, or if rapid switching back and forth ever jumps. Run it while Cathemeral or the harness is dimming, with different levels for the two apps. `e2e.sh` runs it. It never writes gamma.
- **`peek`** (`swift run peek [--built-in]`) prints each display's gamma peak: about 1.0 undimmed, about the level when dimmed. `peek --built-in --until 1.0000 --within 2` waits for that peak and prints how many milliseconds it took. It never writes gamma, so running it changes nothing.
- **`other-app`** stands in for another app that writes gamma, such as f.lux. It captures the built-in display's table at launch, then takes `write <fraction>` (that table scaled, as a tint) and `touch` (the current table written back unchanged) on stdin. Its exit, at end of input, makes WindowServer reset every display. It is the only tool that writes gamma, and `scripts/check` allows it by name.
- **`harness`** is the engine with no UI (plus the activation monitor and window tracker), driven by commands on stdin (`set`, `activate`, `hide`, `displays-changed`, `suspend`, `unsuspend`, `stall`, `resume`, `status`, `quit`). Run it as `harness <path-to-GammaWatchdog>`: like the app, it keeps a watchdog through `SafetyNet`. The command list is at the top of `Sources/harness/main.swift`. Extend `e2e.sh` with new scenarios as tickets add behaviour (ramps, handover, displays, signals).

`e2e.sh`, `harness` and `other-app` follow the gamma-safety standards in `CODING_STANDARDS.md`: every way out ends the harness and `other-app`, whose exits make macOS reset their gamma.
